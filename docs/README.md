# Software project documentation starter

This directory contains **optional, reusable Markdown templates** for software projects. It contains no approved product requirements, accepted architecture decisions, completed research, or confirmed security findings for your application.

Use these files to document the software you are creating. Do not treat template headings, prompts, or examples as project facts.

## Choose what you need

| Area | Use it for | Start with |
| --- | --- | --- |
| [Requirements](requirements/README.md) | Approved behavior, constraints, and acceptance criteria | `requirements/PRODUCT_TEMPLATE.md` |
| [Architecture decisions](adr/README.md) | Consequential technical decisions and their tradeoffs | `adr/ADR_TEMPLATE.md` |
| [Research](research/README.md) | Evidence and unresolved questions | `research/QUESTIONS_TEMPLATE.md` |
| [Security](security/README.md) | Observed issues, threats, and their resolution | `security/FINDING_TEMPLATE.md` |
| [Design](design/README.md) | Shared interface and content rules, when useful | `design/SYSTEM_TEMPLATE.md` |

## Use the templates

1. Inspect the real project, its existing documentation, and its current behavior before adding files.
2. Keep existing project records. Do not overwrite them with these templates.
3. Copy only the template that serves a current need. Rename the copy to a project-specific filename.
4. Replace every placeholder with confirmed information. Remove sections that do not apply.
5. Record who approved a requirement or decision and what evidence supports a finding. Until approval, label the record as proposed or draft.
6. Link important requirements and decisions from the tests, code, or change requests that depend on them.

For an existing project, reuse its documentation conventions when they work. For a new project, start with the smallest useful set of records. An empty template is not a requirement to fill it in.
