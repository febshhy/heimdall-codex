## Functional states

- [ ] Required actions are available to authorized users and unavailable to others.
- [ ] Loading, empty, success, error, denied, and offline states behave as specified where applicable.
- [ ] Errors explain the next useful action without exposing sensitive information.
- [ ] Data shown in the interface agrees with the authoritative application state.

## Interaction and accessibility

- [ ] Navigation, focus order, keyboard actions, and focus restoration work on supported platforms.
- [ ] Relevant assistive technology and accessibility requirements are tested.
- [ ] Zoom, narrow screens, long text, and supported languages preserve essential meaning.
- [ ] Motion and media respect relevant user and platform preferences.

## Presentation and content

- [ ] Shared tokens and terms match approved project records, where they exist.
- [ ] The most important content remains understandable at realistic display sizes.
- [ ] User-facing factual claims have appropriate evidence.
- [ ] Visual metaphors do not replace required instructions or status information.
