# Research foundation and evidence boundaries

Reviewed 2026-11-09. These are externally maintained references; recheck when standards or search platforms change.

| Topic | Source | Applied conclusion | Evidence status |
| --- | --- | --- | --- |
| User-centered design cycle | Design Council, Framework for Innovation, https://www.designcouncil.org.uk/resources/framework-for-innovation/ | Discover/Define/Develop/Deliver is iterative, not a mandatory ceremony | Official method |
| Heuristic review | Nielsen Norman Group, 10 heuristics, https://www.nngroup.com/articles/ten-usability-heuristics/ | Visibility, match to user language, user control, error prevention, recognition | Professional guidance |
| Visual organization | Nielsen Norman Group, visual principles, https://www.nngroup.com/articles/principles-visual-design/ | Hierarchy, scale, balance, contrast, Gestalt improve clarity | Professional guidance |
| Visual grouping | Nielsen Norman Group, proximity, https://www.nngroup.com/articles/gestalt-proximity/ | Proximity conveys relationships; test at responsive breakpoints | Professional guidance |
| Risks of generated UI | Nielsen Norman Group, UX debt, https://www.nngroup.com/articles/ai-ux-debt/ | Faster generation must be matched by review and user evidence | Professional analysis, not a universal measurement |
| Anti-slop definition | Nielsen Norman Group, AI glossary, https://www.nngroup.com/articles/artificial-intelligence-glossary/ | Plausible, low-substance, unverified output is the issue; no objective style fingerprint | Working definition |
| UI copy | GOV.UK Service Manual, https://www.gov.uk/service-manual/design/writing-for-user-interfaces | Lead with user-language, concise tasks, and clear recovery | Public service guidance |
| Inclusive design | Microsoft Inclusive Design, https://learn.microsoft.com/en-us/learn/modules/write-inclusive-windows-apps/ | Recognize exclusion, learn from diverse users, solve for one/extend to many | Established design approach |
| Web accessibility | W3C WCAG 2.2, https://www.w3.org/TR/WCAG22/ | Use applicable normative success criteria and test at AA baseline | Standard; does not apply verbatim to every native platform |
| Web component patterns | W3C WAI APG, https://www.w3.org/WAI/ARIA/apg/ | Keyboard patterns, names, role/state semantics for custom web controls | Guidance, not complete design system |
| SEO and authenticity | Google Search Essentials, https://developers.google.com/search/docs/essentials | People-first content and technical discoverability for indexable pages | Search provider guidance |
| AI-generated public content | Google Search Central, https://developers.google.com/search/docs/fundamentals/using-gen-ai-content | AI output requires accuracy checks; scaled low-value content risks policy violations | Provider policy |
| JS web indexing | Google Search Central, https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics | Crawlable links, rendered content, meaningful statuses, metadata | Web-only technical guidance |

**Evidence hierarchy.** Normative standards and official platform documentation define technical compliance. Usability heuristics and design process are decision support. Slop detection is a subjective heuristic; do not assert that a visual pattern or phrase proves AI authorship. User testing is needed to verify an interface meets a specific audience's needs.

**Unknown:** effectiveness of this new skill in your particular agents/projects is not measured yet. Establish a baseline and compare outputs on the same tasks before claiming higher quality.
