# Repository Writing Standard

Use short, direct technical prose.

- Use one term for one concept inside a module. Use the authoritative module model or glossary when present.
- Prefer active voice.
- Use imperative verbs for procedure steps.
- Put one instruction in each procedural sentence when practical.
- Keep one topic in each paragraph.
- Use lists and tables when they improve retrieval.
- Preserve exact code identifiers, commands, product names, and quoted source text.
- Separate facts, inferences, estimates, opinions, and unknowns when the distinction matters.
- Do not claim a check, review, or approval happened when it did not happen.
- State the audience's actual task early. Delete generic preambles, filler and repeated conclusions.
- For substantive explanations, ensure each cause, mechanism and consequence follows from the preceding facts.
- Do not turn a hypothetical example or metaphor into proof of a feature or test result.
- Apply `$content-writing` and its writing-quality gate to public or user-facing documentation; preserve the author’s intended style.

Do not simplify wording in a way that changes a requirement or technical meaning. Do not classify authorship from a word list or writing style.
